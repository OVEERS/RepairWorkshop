Дорожная карта проекта
Принципы порядка
Сначала фундамент, потом контент, потом красота. Переписывать архитектуру под готовый контент дороже, чем наоборот.
Каждый этап заканчивается играбельной версией. Если этап нельзя запустить и проверить, он слишком большой.
Данные трогаем как можно реже. Чем больше игроков и полей в сохранении, тем больнее менять схему. Поэтому ProfileStore и личные мастерские идут до большого контента.
Красота в конце. Цикл должен быть интересным на серых кубиках.

Сроки примерные, для одного человека, который параллельно учится.

Этап 0. Инфраструктура (2-4 дня)

Зачем сейчас: кода пока мало, и перенести его в Git проще всего именно сейчас.

VS Code + Rojo (код живёт в файлах, Studio только синхронизируется)
Git + GitHub (история, откат, ветки)
Линтер Selene и форматтер StyLua
Структура папок: src/server, src/client, src/shared
Регулярные бэкапы .rbxl и отдельный тестовый плейс (dev) и боевой плейс (prod), чтобы тесты не трогали данные реальных игроков
Файл ROADMAP.md и CHANGELOG.md в репозитории

Готово, когда: проект собирается из Git одной командой, а ты можешь откатить любой коммит.

Этап 1. Укрепление базы (1 неделя)

Зачем: сейчас игра работает, но новичок в ней потеряется, а код держится на именах объектов.

Счётчик места «Сломано 4/10» в InventoryUI
Туториал (пошаговые подсказки): приём → разборка → ремонт → заказ → продажа. Стрелка или подсветка нужной станции, текст в уведомлении
Адаптивный UI: большая часть аудитории Roblox играет с телефона. Проверка в эмуляторе (Test → Device), кнопки не меньше 44px, нормальные отступы
Единый модуль UI (UIKit): кнопки, окна, карточки. Сейчас каждый скрипт копирует свои new(...)
Единые константы и ремоуты: один модуль вместо строк, разбросанных по файлам
Очистка и защита: лимит частоты запросов на ремоутах (rate limit), проверка типов везде
Логирование ошибок (pcall + запись в лог), чтобы видеть, что ломается у игроков

Готово, когда: человек, который тебя не знает, проходит первый цикл без твоих объяснений.

Этап 2. Личные мастерские / плоты (1-2 недели)

Зачем: самое большое архитектурное изменение. Сейчас станции общие, а значит, нельзя ни кастомизацию, ни гостей, ни нормальную масштабируемость.

Шаблон мастерской в ServerStorage: модель со станциями и тегами
Выдача плота при входе (слоты 1..N), освобождение при выходе
Привязка станций к владельцу: атрибут OwnerUserId; сервер проверяет, что игрок использует свои станции (а позже станции друга, если разрешено)
Телепорт к своему плоту, спавн рядом
Общая зона (хаб / площадь): доска заказов, магазин, продажа остаются общими или переезжают в плот (решаем на этапе)
Лимит игроков на сервер под число плотов (8-12 для начала)
Подготовка под расширение мастерской (разблокировка новых слотов под станции)

Готово, когда: 4 человека зашли на один сервер, у каждого своя мастерская, чужие станции не работают.

Этап 3. ProfileStore и данные (1 неделя)

Зачем: пока в сохранениях нет блокировки сессий, при быстром переходе между серверами можно потерять или дублировать прогресс. Делаем до расширения данных.

Переход на ProfileStore (сессионные блокировки, автосейв, корректный выход)
Версионирование данных (Version) и миграции: функция, которая приводит старые сейвы к новой схеме
Вынос сериализации в отдельный модуль (PlayerData), а не в кучу папок-значений. Папки остаются только как «зеркало» для UI
Защитные проверки: лимиты значений, санитайзинг при загрузке
Админ-команды для тестов: выдать монеты, сбросить данные, выдать предмет (только для твоего UserId)
Резервные копии: ключ с суффиксом версии при крупных миграциях

Готово, когда: два быстрых захода/выхода подряд не ломают сейв, а старые данные успешно мигрируют.

Этап 4. Глубина геймплея (3-5 недель, разбивается на под-этапы)

Зачем: сейчас цикл «взял → разобрал/починил → продал» быстро надоест. Нужны решения, а не только действия.

4.1 Сборка нового (вернуться к исходной идее)
Крафт из запчастей: собираешь предмет, которого нет среди заказов (например, радио из провода, платы и корпуса)
Чертежи: открываются за репутацию, дают доступ к рецептам
Качество собранного зависит от мини-игры
4.2 Инструменты и износ
Отвёртка, паяльник, пинцет, мультиметр: у каждого прочность и уровень
Некоторые предметы требуют конкретный инструмент (микросхемы только паяльником)
Ремонт инструментов, замена, апгрейд. Вторая валюта прогресса: инструменты открываются за материалы, а не только за монеты
4.3 Качество и редкость
Состояние предмета: ржавый / обычный / хороший / коллекционный
Состояние влияет на цену, на шанс получить редкие детали при разборке
Редкие детали и «находки» при разборке (сюрприз-элемент)
4.4 Разнообразие мини-игр
Разные станции требуют разных механик: таймер-шкала (уже есть), подбор проводов по цвету, закручивание винтиков, паяние по точкам
Ремонт сложных предметов в несколько этапов
4.5 Заказчики и события
Категории клиентов: бабушка (сентиментальные вещи, платит щедро), коллекционер (редкое), студент (бюджет, но много заказов)
Особые заказы с историей (цепочки на 3 шага)
События: «Распродажа» (цены ×1.2), «Наплыв заказов», «Блошиный рынок» (редкие детали со скидкой)
Дневной цикл или недельные испытания («почини 10 радио»)
4.6 Прогресс и цели
Уровень мастера + древо навыков (скорость, шанс идеального ремонта, больше места)
Достижения и коллекция («каталог предметов»: чего ты уже чинил)
Ежедневные задания и серия входов (мягкая, без наказания за пропуск)
4.7 Экономика
Таблица баланса (цены, время, доход в час) в Google Sheets, а не в голове
Принцип: каждый апгрейд окупается за 5-15 минут на ранних уровнях, дольше на поздних
Инфляционные стоки: ремонт инструментов, налоги на аренду, дорогие косметические предметы

Готово, когда: сессия в 30 минут ощущается разнообразной, а у игрока всегда есть 2-3 цели на выбор.

Этап 5. Закрытое тестирование (2 недели, потом постоянно)

Зачем: твоё мнение о балансе и интересности ненадёжно, потому что ты знаешь игру изнутри.

Тест с друзьями и семьёй (сестра как первый тестер!)
Аналитика: сколько игроков доходит до первого заказа, где бросают, сколько длится сессия (AnalyticsService Roblox + собственные события)
Сбор багов в простом списке (GitHub Issues)
Нагрузочные проверки: 10-12 игроков одновременно, утечки памяти, количество Instance
Тесты экономики: можно ли «сломать» игру бесконечными монетами

Готово, когда: новый игрок в среднем играет дольше 10 минут и понимает, что делать дальше.

Этап 6. Полировка (4-8 недель)

Зачем: здесь появляется то самое ощущение «качественного» плейса, которое тебя зацепило у сестры.

Модели: станции, предметы, детали, интерьер мастерской (Blender, либо ассеты Creator Store + доработка)
Освещение и атмосфера: Future-освещение, тёплые лампы, пыль в лучах, цветокоррекция
Анимации: персонажа за работой, открытие ящиков, детали вылетают из разобранного предмета
Звук: стук инструментов, щелчки, фоновая музыка, звук монет, звук выдачи заказа
Эффекты: искры, дым, частицы при починке, подсветка идеального ремонта
UI в одном стиле: единая палитра, иконки, шрифты, анимации появления окон (TweenService)
Иконки предметов и деталей (рендер моделей в ViewportFrame)
Читаемость и подсказки (tooltips), настройки (громкость, графика)
Доступность: цвет не единственный источник информации, размер шрифта

Готово, когда: скриншот игры хочется кому-то показать.

Этап 7. Социальные функции (3-5 недель)

Зачем: социальность удерживает игроков, а к этому моменту база уже стабильна.

Визиты в мастерские друг друга (дверь или портал), просмотр кастомизации
Редактор мастерской: расстановка декора, обои, полы, цвета (хранится в данных плота)
Магазин косметики (за монеты, а позже за Robux)
Торговля между игроками: безопасный обмен (двухстороннее подтверждение, блокировка при изменении)
Кооп-мастерская (опционально): двое работают в одной мастерской, делят заказы
Таблицы лидеров (репутация, количество починенного)
Друзья: бонус при игре с друзьями, помощь с заказами
Чат-эмоции и быстрые реакции
Готово, когда: игроки заходят друг к другу в гости без твоей подсказки.

Этап 8. Подготовка к релизу (2-3 недели)

Зачем: хорошая игра без страницы и оформления не получает игроков.

Монетизация (этично): Game Passes (двойная скорость, дополнительный слот плота, VIP-декор), Developer Products (пакеты монет), никаких pay-to-win в соревновательных элементах
Страница игры: иконка, миниатюры, трейлер, описание, теги
Соответствие правилам Roblox: фильтрация текста, возрастной рейтинг (анкета), политика платных случайных предметов (если будут лутбоксы, проверить правила)
Оптимизация: StreamingEnabled для больших карт, пул объектов, снижение числа скриптов на станцию
Поддержка устройств: телефон, планшет, консоль (геймпад: управление и UI навигация)
Локализация (английский сразу, остальное по мере роста)
Мягкий запуск на малой аудитории, наблюдение за метриками

Этап 9. Живая поддержка (постоянно)
Регулярные обновления (раз в 2-3 недели: новые предметы, заказчики, события)
Сезонные события (Хэллоуин: проклятые вещи; Новый год: гирлянды для починки)
Баг-фиксы по отзывам, баланс по метрикам
Сообщество: Discord, группа Roblox, секретные коды
Журнал обновлений (CHANGELOG) в игре

Банк идей (без привязки к этапу)
Погода и время суток в мастерской (дождь: больше заказов, но с влажными дефектами)
Питомец-помощник: робот, который автоматически разбирает мелочь
Автоматизация (мост к исходной идее с заводами): ленты, станки, которые разбирают сами. Добавляются осторожно, с серверной симуляцией по таймерам вместо физики, чтобы не было рассинхрона
Аукцион редких деталей между игроками
Музей: витрина с лучшими починенными предметами, которую видят гости
Мини-расследования: у каждой вещи история, найденная внутри при разборке (записка, фото)
Брак и риск: шанс сломать деталь при неидеальной мини-игре
Гильдии мастеров: общие заказы на сервер
Режим «день старьёвщика»: события раз в неделю с огромными кучами хлама
Продвинутые клиенты с характерами (требовательный, торгуется, оставляет чаевые)
Сезонный пропуск (battle pass-подобная система)
Режим без таймеров (уютный) для тех, кому важна расслабленная игра
